> **摘要**：本文介绍了 HumanLayer 团队推出的 `/show-me` skill，旨在解决编码代理（coding agent）输出大量冗长文字的痛点。通过引导代理使用组件树、调用栈、Mermaid 图表、文件布局、伪代码、diff 语法、HTML 原型等紧凑可视化形式代替长篇大论，`/show-me` 让代理与开发者的沟通更加高效。文章展示了多种可视化表示法的具体样式和适用场景，并提供了安装使用方式。核心理念是：人的视觉皮层经过数百万年进化，天生擅长处理丰富的视觉信息，工具应顺应这一特点。

tl;dr 让你的代理用可视化方式对话，而不是大段散文。

```bash
npx skills add humanlayer/skills --skill show-me
```

比 HTML 更轻、更快，足以应对大多数开发工作场景的问题。

#### 我真的受够了

代理在纸面上越来越智能了，但使用体验在这条维度上却明显变差了。

人们曾经喜欢 Claude 的东西——它的语气、个性、它的"灵魂"——已经在 RL 训练的深渊中被洗掉了。

Sol 稍微没那么尴尬，但仍然经常甩出一堆让人眼睛发直的行话。

这是我最近收到的一条回复。这种情况每天发生好几次。

#### 我的方案：show me

我们一直在尝试内部工具来改善这种情况，特别是针对编码场景，并以一个名为 show-me 的 skill 发布出来。

它今天已经在 HumanLayer 中上线了。如果你想在任何其他编码代理中使用它，可以这样获取：

```bash
npx skills add humanlayer/skills --skill show-me
```

或者，获取内置了内联 HTML 和一等公民图表支持的 HumanLayer 版本：

```bash
brew trust humanlayer/humanlayer
brew tap humanlayer/humanlayer
brew install humanlayer
```

如果你看过 [Coda Hale 关于基础设施系统中直觉 vs 注意力的演讲](https://www.youtube.com/watch?v=e_6gkfTomUQ)，这个想法某种程度上受其启发：

- 分析信息是困难且 exhausting 的
- 你的视觉皮层经过数百万年的进化，天生擅长毫不费力地处理丰富的视觉信息
- 工具应该顺应这一点

> 就像斧头必须贴合人手才有用一样，软件也必须贴合人脑才有用

**/show-me** 提示代理使用简洁的可视化方式解释当前发生的事，而不是大段散文。

这对于[程序设计](https://hlyr.dev/wsff-gh#program-design)特别有用——这是现在很多人跳过、但我认为至关重要的阶段。在代理开始写代码之前，你应该先讨论代码的形状（类型、签名、调用栈）。

同样的技术也可以用于事后浏览大型 diff，了解在审查中需要深入挖掘什么。

#### 内部包含什么

#### 组件树

前端同理，保留重要的状态钩子和模块边界，其他一切去掉。

我早在 2025 年 12 月就在 Twitter 上分享过这个：

> 2025年12月11日
> 
> 我一直在提示 Claude 像这样为我生成组件树，当我重构组件并消除复杂状态和过多的 useEffects 时。这在编写实际计划之前，对与代理（以及团队）的思维对齐超级有帮助。

#### 调用栈

对于编排或控制流工作，或者任何后端类型的问题，Dillon 给了我们这种"调用栈"形状。

> 5月28日
> 
> 我的"计划"在很大程度上看起来像是伪代码，主要由类型/接口组成，它们如何组合，以及它们的边界 我最近开始包含调用栈——这对我和代理在实现时都非常有帮助

Tanishq 甚至写了一个工具直接从 AST 计算调用栈：

> 8月8日
> 
> 调用栈差异完全改变了 我阅读 markdown 计划的方式 谢谢你 @dillon\_mulroy

#### 图表

经典方案。如果你的聊天界面支持内联 Mermaid，这些图表可以帮大忙。（有时它们仍然是垃圾，但通常比读文字好）

选择很多。我们最喜欢状态图和时序图。

#### 文件布局

一个浅层文件树，每一条目一行职责描述。适合回答"这个代码放在哪里"以及划定重构范围。

#### 伪代码

特别是对于算法类内容，伪代码可以更简洁。

#### 类型与签名

代码在还不存在时的形状——那些对架构文档来说太底层、但代理仍然会搞错的东西。

```typescript
interface Item {
  id: ItemId
  parentId: ItemId | null
  // ...
}

interface Cursor {
  position: ItemId
  direction: 'up' | 'down'
  // ...
}

resolveTarget(items: Item[], cursor: Cursor) -> ItemId | null
```
