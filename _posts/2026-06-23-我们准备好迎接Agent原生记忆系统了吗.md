#### 摘要

LLM Agent 的记忆已从简单的检索增强机制快速演变为一个数据管理系统，支持持久化信息的存储、检索、更新、整合以及在 Agent 执行过程中的动态生命周期治理。尽管如此，现有评估仍主要通过端到端任务成功指标（如 F1、BLEU）来基准测试 Agent 记忆，同时将底层系统视为一个单体黑盒。因此，关键的系统级关注点——包括运营成本、跨记忆模块的架构权衡、以及动态知识更新下的鲁棒性——仍然探索不足。

本文从**数据管理**视角对 Agent 记忆进行了系统性的实验研究。我们提出了一个分析框架，将 Agent 记忆分解为四个核心模块：**记忆表示与存储**、**记忆抽取**、**记忆检索与路由**、**记忆维护**。在此框架下，我们在 5 个基准工作负载（涵盖 11 个数据集）上评估了 12 个代表性记忆系统和 2 个参考基线。

广泛的端到端评估表明：**没有单一架构在所有场景中占据主导地位**；相反，效果在很大程度上取决于记忆结构与工作负载瓶颈的对齐程度。此外，通过细粒度消融研究，我们量化了各模块对表示保真度、检索精度、更新正确性和长期稳定性的单独影响。最后，我们揭示了现实工作负载下的成本-性能权衡，表明**局部维护比全局重组更具成本效率**。

#### 1. 引言

LLM Agent 的快速演进催生了大量关于构建 Agent 记忆的研究和工业实践，即支持长期有状态执行和个性化交互的 LLM Agent 数据管理系统。

##### 现有 Agent 记忆系统的架构类型

如图 1 所示，现有 Agent 记忆系统跨越了多种架构设计：

1. **流式与反思记忆系统**（如 MemoryBank）：将经验维护为带时间戳的记忆流，周期性地将其总结为更高级别的反思写回流中。

2. **分层分级记忆系统**（如 MemGPT/Letta）：将记忆组织为多个层级，具有不同的容量和访问属性，将核心记忆与归档存储分离，并在层级之间进行显式移动（如淘汰和提升）。

3. **知识图谱记忆系统**（如 Mem0^g、Zep）：以结构化形式（如时序知识图谱）表示实体、关系及其时间演变，通常包含实体消歧和冲突解决。

4. **组合混合记忆系统**（如 A-MEM）：将 schema 感知的记忆对象路由到多个存储基底，显式分离运行时状态（如 KV 缓存）和长期存储（如向量、图、关键词索引），由专门的维护模块管理。

##### 现有评估的局限性

1. **覆盖不足**：未能在统一工作负载下评估众多代表性记忆架构，使系统间的原则性比较困难。
2. **指标单一**：主要依赖单侧、端到端任务成功指标（如 F1 和 BLEU），未能显式隔离和测量检索保真度、动态更新鲁棒性、长期稳定性等多维度性能指标。
3. **忽视运营成本**：很少从系统视角测量关键运营成本，如索引构建时间和查询延迟。
4. **黑盒处理**：将记忆系统视为单体黑盒，而非将其分解为基础数据管理模块进行隔离的细粒度分析。

##### 本文贡献

1. **技术分解与分类法**（第 3 节）：将 Agent 记忆分解为四个核心组件，并为每个组件建立结构化分类法。
2. **整体端到端性能评估**（第 4 节）：在 5 个基准工作负载（11 个数据集）上，对 12 个代表性记忆系统进行评估，从五个视角考察：任务有效性、检索保真度、动态更新鲁棒性、长期稳定性、运营成本。
3. **细粒度技术组件评估**（第 5 节）：通过系统性生成每次仅修改一个模块的对照变体，量化其性能权衡。
4. **深刻发现**：总结了 6 大关键发现（详见下文）。

#### 2. 预备知识

##### 记忆类型

对于 LLM Agent，需要记忆的信息种类繁多：对话历史、工具执行日志、蒸馏事实、用户偏好等。遵循认知框架，记忆可沿两个轴组织：

1. **时间轴**：短期记忆持有当前会话的易失性状态；长期记忆跨会话持久化。
2. **功能轴**：长期记忆进一步分为——具体过去事件（情景记忆）、抽象化的事实知识（语义记忆）、可复用的行动策略（程序性记忆）、用户偏好。

##### Agent 记忆的形式化定义

**Agent 记忆** $\mathcal{M}$：维护超越单次推理步骤的累积状态的持久化数据管理对象，并在未来推理和行动中使其对 Agent 可访问。

**Agent 记忆系统**形式化为四模块元组：$\mathcal{M}_{sys} = \langle \mathcal{R}, \mathcal{S}, \mathcal{Q}, \mathcal{U} \rangle$

- **(1) 记忆表示与存储** $\mathcal{R}$：定义逻辑和物理记忆格式的映射——逻辑表示（token 序列、向量、知识图谱、树、复合结构）；物理存储（瞬态寄存器、单引擎数据库、多引擎后端）。
- **(2) 记忆抽取** $\mathcal{S}$：控制异构输入流如何转换为逻辑记忆原语的机制——原始序列拼接、无 schema 语义抽取、有 schema 约束的结构化抽取。
- **(3) 记忆检索与路由** $\mathcal{Q}$：基于查询上下文动态识别相关记忆子集——原生注意力检索、语义 KNN 搜索、拓扑子图遍历、自主 Agent 路由、多阶段混合执行。
- **(4) 记忆维护** $\mathcal{U}$：管理记忆条目动态生命周期的策略——冲突解决与版本控制、容量管理、语义整合。

##### 与 RAG 和上下文工程的区别

- **RAG** 通常作为无状态、只读的检索原语运作。
- **上下文工程** 是在每次推理轮次中管理有限 LLM 上下文窗口的实践。
- **Agent 记忆系统** 是管理 Agent 特定状态的持久化可更新基础设施，治理完整的长期记忆生命周期。

##### 与传统数据库工作负载的区别

1. 记忆访问是**语义性**的，而非纯基于谓词。
2. 记忆内容在**持续且可能矛盾的观察**下演变。
3. Agent 记忆工作负载在访问模式和粒度上**高度异构**。

#### 3. 方法概述

##### 3.1 记忆表示与存储

###### 3.1.1 逻辑表示

**❶ Token 级序列表示**

将记忆建模为扁平的一维序列，无显式结构化抽象：

- **显式离散文本 Token**：如 Mem0 将记忆隔离为离散自然语言事实；MemoChat 将多轮对话结构化为 JSON 块。
- **隐式连续向量 Token**：将记忆编码为连续向量（外部嵌入或模型侧潜在状态如 KV 缓存张量）。

**❷ 图与树拓扑表示**

将记忆抽象为结构化的图和树拓扑：

- **时序知识图谱**：如 Zep 将记忆分区为时序感知知识图谱（情节、实体、社区子图）；Mem0^g 形式化为有向标记图。
- **层次树结构**：如 MemTree 将知识组织为递归层次结构——叶节点保留细粒度观察，祖先节点保留广泛语义抽象。

**❸ 异构复合表示**

将非结构化文本与高度结构化元数据（时间戳、类别标签、向量嵌入、网络链接）打包为单一功能单元：如 MemOS 的 MemCube。

###### 3.1.2 物理存储与索引

- **❶ 瞬态上下文内寄存器**：将记忆完全保持在活动硬件状态中（动态上下文窗口或 KV 缓存）。
- **❷ 专用单引擎存储**：如密集向量数据库（Mem0、MemTree）、图数据库（Zep、Mem0^g 使用 Neo4j）、关系型 SQL 引擎（LightMem）。
- **❸ 异构多引擎存储**：如 SimpleMem 并发维护密集嵌入、稀疏 BM25 索引和 SQL 谓词；MemOS 融合向量和图数据库。

##### 3.2 记忆抽取

- **❶ 原始序列拼接**：绕过显式抽取提示，直接作为原始 token 拼接。
- **❷ 无 schema 语义抽取**：系统性提炼原始输入为独立的高价值信息单元（如 Mem0 提取离散事实语句）。
- **❸ 有 schema 约束的结构化抽取**：提示 LLM 解析原始输入并同步填充严格预定义的结构化 schema（如实体-关系三元组）。

##### 3.3 记忆检索与查询路由

- **❶ 原生注意力检索**：使用 Transformer 原生计算图作为唯一检索引擎（如 MEM1 通过自注意力执行隐式检索）。
- **❷ 语义密集检索**：在连续潜在空间中执行 KNN 搜索（如 Mem0 执行密集相似度搜索）。
- **❸ 拓扑子图遍历**：通过遍历显式关系边来检索信息（如 Mem0^g 递归遍历局部子图）。
- **❹ 自主 Agent 路由**：将检索委托给 LLM 本身，作为自主查询规划器（如 Letta 的 function calling、SimpleMem 的生成式查询扩展）。
- **❺ 多阶段混合执行**：包括顺序混合路由（先粗后精）和并行集成检索（同时 dispatch 到多个索引算法，后期融合）。

##### 3.4 记忆维护

- **❶ 基于时间戳的多版本控制**：通过时间戳元数据和仅追加日志逻辑废弃过期事实（而非物理删除）。
- **❷ 容量驱动的物理淘汰**：包括基于约束的硬淘汰（FIFO、固定 token 限制）和基于分数的优先淘汰（时间衰减、访问频率）。
- **❸ LLM 驱动的语义整合**：包括内联语义压缩（写入阶段合并冗余断言）和工具驱动 CRUD 执行（通过 LLM 工具接口发出显式 CRUD 命令）。
- **❹ 持续参数优化**：作为异步后台进程执行神经优化，修改模型参数而非外部数据库 schema。

#### 4. 端到端评估

##### 评估的五个研究问题

| 编号 | 研究问题 | 核心维度 |
|------|----------|----------|
| RQ1 | 不同 Agent 记忆系统是否成功提升了端到端任务性能？ | 任务有效性 |
| RQ2 | 记忆系统检索存储证据的准确度如何？ | 检索保真度 |
| RQ3 | 记忆系统在动态更新下是否鲁棒？ | 更新鲁棒性 |
| RQ4 | 记忆系统在长期范围内是否保持稳定？ | 长期稳定性 |
| RQ5 | Agent 记忆的运营成本是什么？ | 运营成本 |

##### 4.1 整体有效性（RQ1）

**使用基准**：LoCoMo（长对话 QA）、LongMemEval（多会话长记忆）、DB-Bench（程序性执行）

**关键发现 O1——跨工作负载有效性**：

没有单一记忆架构在所有工作负载中占主导，但通过结构引导过滤保留任务关键证据的方法总体上最具竞争力：
- 结构感知系统在 LongMemEval 上领先（Zep 达到 48.0 LLM Judge Accuracy）
- 混合过滤在 LoCoMo 精确匹配上最强（MemOS 达到 11.5 EM）
- 痕迹保留记忆在 DB-Bench 上最强（Long Context 达到 48.20 EM）

具体而言：
- 时序或图组织记忆对跨会话聚合和事件顺序推理最有用
- 摘要优先或由粗到精路由对长但语义连贯对话中的精确定位有用
- 痕迹保留记忆在正确性依赖于中间状态变化和操作顺序时是必要的

##### 4.2 记忆检索保真度（RQ2）

**关键发现 O1——结构化证据扩展**：

检索保真度不取决于能否早期表面化一个相关记忆，而取决于是否保持了显式组织的记忆结构以收集完整且时间距离较远的证据。

- SimpleMem 达到最高 Recall@1（39.0），但 A-MEM 和 MemTree 在更大检索预算下明显更强（Recall@10 分别达到 85.9 和 80.5）
- 扁平密集检索（Embedding RAG）随证据距离增大急剧下降
- 最具竞争力的系统将记忆组织为结构化证据空间，而非扁平相似度缓存

##### 4.3 记忆演变鲁棒性（RQ3）

**关键发现 O4——时序状态外化**：

没有单一记忆系统在所有面向更新的切片中占主导，但通过结构化组织保留时序有效证据的方法总体上最具竞争力：
- 图或关系组织记忆在直接事实修订上最强（Zep 在 Knowledge Update 上领先，44.4 Substr. EM）
- 关系组织检索在时序分散证据上最强（Cognee 在 Temporal Reasoning 上领先，18.7 Substr. EM）
- 混合过滤记忆在精确最新状态定位上最强（MemOS 达到 8.9 EM）

**关键发现 O5——骨干鲁棒性**：

骨干模型变化改变的是绝对回答质量，而非哪个记忆管道有效——说明稳定的更新行为主要在最终生成之前确定。MemOS 在所有 4 个 LLM 骨干下均保持最强配置。

##### 4.4 长期记忆稳定性（RQ4）

**关键发现 O6——长期证据保持**：

当证据通过显式关系链接或层次整合组织时，记忆在更长范围内更稳定；纯长上下文提示和扁平密集记忆缺乏这种支持，随有效范围增长退化更剧烈。

- SimpleMem 从 Short 到 Medium 几乎不变（35.2 → 34.9），而 Long Context 从 42.6 降至 19.0
- Embedding RAG 随证据距离扩大从 37.1 降至 7.4 Answer F1
- 图或整合记忆系统（Cognee、MemOS、MemoryOS）在相同范围内保持显著更高

##### 4.5 记忆运营成本（RQ5）

**关键发现 O7——局部维护**：

最具成本效率的记忆机制是那些将维护局部化到有界记忆状态子集的机制；反复重组大型全局状态的机制最不高效。

- LightMem 和 MemTree 占据最强效率前沿（LightMem：48.3 归一化效用 / 3.67s 延迟）
- 高效用结构化系统代价高昂：Zep 达到 84+ 效用但需 155.1s
- 在 LongBench 上，LightMem 保持 17.3s，而 A-MEM 升至 552.1s

运营效率取决于每次写入在结构中传播的范围：
- 分段压缩和有界混合检索保持低成本
- 路径局部树聚合在不全局刷新的情况下保留更多效用
- 图级整合、多存储同步或重复全记忆重写产生最重的运营成本

#### 5. 细粒度组件比较

##### 5.1 记忆表示与存储（M1）

**关键发现 O8——内容保真度**：

保留原始对话内容比增加抽象或层次对维持事实召回和推理质量更重要。

- LightMem User-Only Raw 在所有四个指标上达到最佳
- User-Only Summary 在两个基准上都明显更弱
- 更深的 MemTree 仅提供适度提升

主要性能边界是表示保留的可恢复证据量，而非是否应用更强的抽象或更深的结构。

##### 5.2 记忆抽取（M2）

**关键发现 O9——保留覆盖的抽取**：

保留覆盖范围的写入时抽取在事实检索和下游推理之间提供最稳定的平衡。

- 保守的主题分组不太可能拆分持续线程
- 较轻的记忆化更可能保留后续需要组合推理的细节
- 包含用户和助手双方轮次可以保留仅用户抽取可能遗漏的澄清线索

##### 5.3 记忆检索与路由（M3）

**关键发现 O10——规划与融合**：

显式规划和平衡检索融合提供检索有效性的最强改善。

- A-MEM 在 Hybrid-Balanced 下达到最佳（24.6 Ans. F1，27.5 Substr. EM）
- SimpleMem 在 Planning Only 下达到最佳（20.7 Ans. F1，90.6 Recall）
- 在规划之上添加反思并未带来进一步收益

##### 5.4 记忆维护（M4）

**关键发现 O11——保守整合**：

保守整合比延迟刷新或过度粗粒度摘要在维护回答相关记忆方面更有效。

- MemoryOS (Conservative-Merge) 改善了默认设置（Ans. F1: 23.2 → 23.5）
- 延迟刷新降低性能至 20.6
- 强制单主题摘要表现更差

#### 6. 关键发现总结

| # | 问题 | 核心发现 |
|---|------|----------|
| ❶ | 记忆系统在不同工作负载下有效吗？ | 没有单一架构占主导；组合混合系统在对话 QA 上领先，图方法在单跳事实召回上出色但时序推理弱 |
| ❷ | 记忆系统检索证据的准确度如何？ | 显式查询规划和平衡混合搜索最大化上下文相关性；但随时间距离增加检索准确度显著退化 |
| ❸ | 记忆系统在动态更新下鲁棒吗？ | 图方法最可靠地处理知识更新；缺乏生命周期管理的系统返回陈旧事实，导致"过去的幻觉" |
| ❹ | 记忆系统在长期范围内稳定吗？ | 许多仅追加存储随证据变远而灾难性退化；对时间相关查询，原始长上下文检索仍优于多数记忆增强方法 |
| ❺ | 运营成本如何？ | 高度结构化系统产生数量级更高的索引构建时间和查询延迟，但不一致地交付相称的精度增益 |
| ❻ | 各记忆组件何时出错？ | 每层抽象逐步丢弃信息；细粒度 LLM 抽取可能适度提升精度但实质性退化多跳推理；保守整合是最佳默认维护策略 |

#### 7. 结论

本文从数据管理视角对现有 Agent 记忆系统进行了全面综述。我们进行了典型 Agent 记忆系统的全面端到端性能评估，并探索了其适用应用场景。此外，我们通过构建多个记忆模块变体深入研究了各构建块的影响，从而确定了表示、抽取、路由和维护的最有效方法，以及治理运营成本和长期稳定性的最具影响力因素。最后，我们总结了发现，并为用户选择合适的记忆架构提供了指导，同时概述了有前景的研究方向。
