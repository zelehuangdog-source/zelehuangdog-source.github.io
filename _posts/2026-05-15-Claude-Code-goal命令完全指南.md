`/goal` 是目前所有 AI 工具中最省时间的功能。让我们来拆解它的工作原理和最佳使用方式。

你肯定经历过这种场景：

你给 Claude Code 一个任务，它做一轮工作，然后停下来等你说"继续"。你推它一下，它再做一轮，又停了。对于小任务来说这没什么问题。但如果是 200 个文件的重构或者一个完整功能的实现呢？简直让人精疲力尽。

Claude 最近发布的 `/goal` 命令彻底解决了这个问题。

你设定一个完成条件，Claude 会自主地一轮接一轮地工作，直到条件满足。不需要盯着看，不需要输入"继续"。你完全可以离开终端，等它做完了再回来。

下面讲讲它的工作原理、如何用好它，以及它在哪些地方还有不足。

#### /goal 的实际工作原理

机制出人意料地简单：

1. 你输入 `/goal` 加上一个明确的完成条件
2. Claude 执行一个完整的轮次（推理、规划、编辑文件、运行测试等）
3. 一个快速评估模型（默认是 Claude Haiku）读取对话记录，回答一个问题："目标条件满足了吗？"
4. 如果没有——Claude 立即开始下一轮
5. 如果满足了——目标自动清除，控制权交还给你

就这么简单。一个带模型验证退出条件的循环。

#### 什么样的目标是好目标

这是决定你 80% 成败的关键。目标条件需要**具体、可衡量、且能从对话记录中验证**。

有效的目标示例：

```
/goal all tests in test/auth pass and the lint step is clean
```

```
/goal CHANGELOG.md has an entry for every PR merged this week
```

```
/goal every call site of the old API has been migrated and the build succeeds
```

注意其中的规律：每一个都描述了一个**可观测的终态**。Claude 可以运行测试、展示输出，评估器可以确认"是的，所有测试都通过了。"

模糊的目标会导致两种失败模式：Claude 无限循环地试图满足一个不清晰的条件；或者评估器因为没有具体内容可检查而幻觉性地判定成功。两种情况都是白白烧 token。

一个有用的思维模型：

**把 `/goal` 想象成你分配给一个非常较真、永远不会累的初级开发者的工单。写下你会放在那张工单里的明确验收标准。**

#### 为 /goal 的成功配置你的项目

`/goal` 命令在 Claude 已经理解你的项目时效果最好。三件事能带来巨大差异：

**项目根目录的 CLAUDE.md。** 定义架构决策、编码规范和你的"完成标准"（Definition of Done）。Claude 在每一轮中都会自动读取它。

**用于自动验证的 Hooks。** 每次文件编辑后自动运行 lint 或类型检查，让 Claude 在运行过程中就能发现问题。

**启用 Auto 模式。** 减少工具使用的权限确认提示。如果不开启，一个 30 轮的运行会因为每次文件写入都要等你批准而频繁卡住。

#### 值得尝试的工作流模式

将 `/goal` 与 Agent View（多个 Claude Code 会话的仪表盘）结合使用，你就相当于在管理一个分布在代码库不同部分的自主 agent 团队。

#### 它的不足之处

**模糊目标导致 token 浪费。** 宽泛的条件意味着 Claude 在没有进展的轮次上空转。

**评估器只能看到对话记录。** 如果 Claude 没有明确打印测试结果或文件 diff，评估器就无法验证。

**复杂的多步骤目标会让它不堪重负。** "重新设计认证、添加 OAuth、写测试、更新文档、部署"——一个目标塞太多了。拆分成多个连续的目标。

**没有内置的 token 预算。** Claude 会持续工作直到完成或被中断（Ctrl+C）。社区插件可以添加 token 上限和对抗性审查来应对长时间运行。

#### /goal vs. /loop vs. Stop Hooks

| 方式 | 适用场景 |
|------|---------|
| `/goal` | 条件经模型验证后停止。最适合**基于结果的工作** |
| `/loop` | 按时间表重复执行。更适合**轮询或周期性任务** |
| Stop Hooks | 提供自定义评估逻辑。**更灵活，但配置更多** |

对于任何有明确终态的编码任务，`/goal` 就是正确的选择。

#### 现在就试试

如果你不确定怎么描述你的目标，可以让 Claude 帮你写。在运行 `/goal` 之前，粘贴类似这样的内容到 Claude Code：

```
Write me a /goal prompt. Ask me what I'm trying to do first, then keep asking 
follow-up questions until you can describe 'done' in specific, measurable terms.
```

拿到它给你的结果，在前面加上 `/goal`，然后运行。之后关掉终端去做别的事情。

从小范围的任务开始，再逐渐过渡到更大的运行。条件越精确，结果就越可靠。

这个功能并不能解决所有问题。但对于任何你能写出明确终点线的任务，它消除了 AI 辅助编程中最大的摩擦：**你坐在那里，一遍又一遍地按回车。**
