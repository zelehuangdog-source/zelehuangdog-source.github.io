你的 Agent 记住了一切，却什么都不理解。

大多数 Agent 记忆系统优化的是召回率。而更难的问题是该遗忘什么——或者更准确地说，一开始就不该存储什么。

默认的 Agent 记忆流水线是这样的：把原始文本丢给 LLM，让它提取实体和关系。模型自行决定类型、标签、属性——全凭它自己。

结果就是知识图谱表现得像一个昂贵的向量存储。实体类型坍缩成通用标签，关系扁平化为一个"RELATES_TO"。

图谱里有数据，但没有任何查询能精确地触达它。

问题不在检索，而在结构。而修复方法正是 AI 技术栈其他地方早已奏效的模式：在生成之前约束输出空间，而非生成之后。

**实体（Entities）** 定义了 Agent 被允许记住什么。带有类型字段和描述性文档字符串的 Pydantic 模型，用领域词汇取代了 LLM 从未被训练过的猜测。

**边（Edges）** 定义了事物如何连接。关系类型上的源/目标约束意味着图谱只能形成合法连接。如果你的 schema 中没有连接 Project 到 Competitor 的边，那么这种关系就不可能存在于记忆中。

**时序分辨率（Temporal Resolution）** 处理"曾经为真"与"当前为真"的区别。事实解析（Fact Resolution）会使过时的边失效，同时保留历史，因此图谱永远不会悄悄提供过期状态。

Schema 在流水线的两个节点引导提取（实体提取和事实提取），而解析与时序处理在下游自动运行。

你定义要寻找什么，系统负责去重、矛盾检测和时间窗口处理——无需额外配置。

一个实用的约束：10 种实体类型、10 种边类型、每种类型 10 个字段。这迫使你建模真正重要的 80%，而非试图追求完备性。从 3-4 种开始，仅在检索失败时才扩展。

Zep AI 的 Graphiti 以完全开源的时序知识图谱库形式实现了上述所有能力：基于 Pydantic 的本体定义、schema 引导的提取、实体解析、事实解析，以及开箱即用的时间窗口处理。
