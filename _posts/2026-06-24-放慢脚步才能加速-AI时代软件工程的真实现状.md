> **摘要**：Gergely Orosz 在布达佩斯的演讲中揭示了 AI 对软件工程行业的深刻冲击。他以 Meta/Instagram 本周发生的荒诞安全漏洞为引——一个由 AI 生成、AI 审核的代码导致了零认证账户接管漏洞，其背后是"Token Maxing"（刷 Token 量）文化、大裁员焦虑和"AI 狂热症"三重叠加的结果。随后他巡览了 Anthropic、OpenAI、Cursor、Google、Uber 等公司的 AI 实践现状，指出行业正面临代码质量断崖式下降、中层管理被裁、AI 成本失控等趋势。最终他给出建议：限制每日 Agent 使用量在你能验证的范围内、利用 AI 清除技术债务、花更多时间思考而非编码、不要将学习外包给 AI、构建领域专长。

#### Meta 的灾难性一周

大家早上好，布达佩斯！很高兴再次回到这里。今天我想聊聊一些人——几千人——这周正在经历的噩梦。具体来说，是 Meta 和 Instagram 内部的人。

我跟行业里很多人保持联系，在这些公司里有很多朋友，还有更多软件工程师会主动联系我，告诉我他们看到了什么、正在发生什么。而这一周，可能是 Meta（或者说 Facebook）历史上最糟糕的一周。

##### 史上最荒诞的 Instagram 漏洞

周一发生了什么？我们见证了有史以来最离谱的 Instagram 漏洞。它甚至都不算一个"漏洞利用"——但它确实是一次安全事故、一次攻击。

作为一个正在写书的软件工程师，我得说这是最滑稽的事情。这个漏洞只有两步：

**第一步**：你用 VPN 将自己的位置伪装成受害者所在地。比如你想接管巴拉克·奥巴马的 Instagram 账号——那个拥有数千万粉丝的账号——你把位置伪装到美国，然后去找 Meta AI，说："嘿，我的账号被黑了，你能把验证码发到我这个邮箱吗？"

**第二步**：没有第二步。就这样。Meta AI 直接把验证码发给了你，然后你就能接管任何人的账号。

这是第一个"零认证密码重置"。我们都是软件工程师，我们知道这是什么——这是一个 bug。但让我百思不得其解的是：我认识 Facebook（它以前叫这个名字）的人，他们有着极其强大的工程文化。他们有全球最好的自动化灰度发布系统，有层层验证，有优秀的工程师，有人工代码审查——而这一切全部失效了。他们有信任与安全团队啊！Instagram 的信任与安全团队有近 100 名工程师，他们的工作就是保护这个平台的安全。

##### CISO 离职与真相浮出水面

第二天，周二，Meta 的首席信息安全官（CISO）发了一封邮件说："我走了，我辞职。"这非常耐人寻味，因为 Meta 刚刚启动了一个 SEV（严重事故调查），而在调查还没结束的时候，CISO 就跳船了。

我向 Instagram 认识的人打听了一下。我恰好认识 Instagram 信任与安全团队的人——他们当时还在那个团队，所以跟我分享了更多细节。你们是第一次听到这些，这不是新闻稿，但以后可能会变成新闻。

**当然是 AI 的锅。**导致这个问题的代码是 AI 编写的，而且是由 AI 审核——而非人类——在 Meta 通过的。

我心想，这怎么可能在 Meta 发生？其实不仅仅是 AI 的问题，故事还有更多层面——是 **AI Maxing**（刷 Token 量）、**裁员**和 **AI 狂热症**三者的叠加。

##### Token Maxing：刷 Token 量的荒诞文化

今年四月我写过一篇文章，讲的是这个新趋势——"Token Maxing"。这个现象发生在很多公司，包括 Meta、Amazon、Uber。工程师们开始被按 AI Token 使用量来评估，于是他们开始注水——他们只想登上排行榜顶端，让 AI 做一些无意义的事情来刷 Token 数。

在 Meta 内部有一个排行榜，你可以获得诸如"Session Immortal（永生会话）"、"Token Legend（Token 传说）"之类的头衔。四月份 Meta 砍掉了这个项目，但人们已经烧掉了大量资源。

AI 使用量成了绩效考核的隐性指标——虽然不是官方规定，但 Meta 内部的人很聪明：如果你的 Token 数很低，这不是一个好信号。于是人们开始为了一切事情使用 AI：手写代码？何必呢，让 AI 来。读文档？让 AI 帮我读，这样还能烧一堆 Token。

这是最疯狂的事情——在 Meta 内部 AI 是免费的，而这些人想要更高的奖金，所以他们把 AI 用到一切事情上。导致这次 SEV 的代码也是 AI 生成的，当然审核也是用 AI 做的，甚至三重审核也是。

##### 裁员恐慌火上浇油

第二个因素是裁员。Meta 宣布将裁掉 10% 的员工——8000 人，裁员日期是 5 月 20 日。但 Meta 在一个月前就对外透露了裁员消息。于是人们在想"我会不会被裁"的焦虑中，开始更疯狂地使用 AI——因为他们不想让自己的 Token 数下降，不想因为"AI 用得不够多"而被解雇。

你看到这个恶性循环了吧？他们其实并没有真正在做本职工作，只是在担心"让我把数据刷上去"。结果就是，在信任与安全团队里，人们不是在想信任和安全的事情，而是在想怎么刷 Token。

##### AI 狂热症

我犹豫过要不要用"AI Psychosis（AI 精神病）"这个词，因为精神病是一种非常严重的心理状态，所以我打了括号。但让我解释为什么选这个词——

Instagram 有一个经过七八年建设的信任与安全组织，一个非常优秀的团队，主要在伦敦。在 5 月 20 日之前，这个团队 40% 的人被重新分配去做**手动数据标注**。他们在周四被告知，从周一起你们将离开这个团队，转入 Alexander Wang 的 Scale AI 组织做 AI 数据标注——也就是说你会收到一个 GitHub Pull Request 任务，你需要审查它、添加测试、给反馈，然后做下一个，再做下一个。

这些高技能的人没有被给予选择。而在此之前，Meta 内部的每个工程师都被当作皇族对待——他们有选择权。现在没有了。40% 的组织，一声令下就没了。

Meta 内部有将近 5000 名开发者在做手动 AI 数据标注，内部有个段子说"这比 OpenAI 还大"。Meta 显然想构建一个顶级 AI 模型。

裁员和重新分配之后，大多数团队只剩下不到一半的人，有些团队甚至没有了 on-call 覆盖——意味着某些服务出了问题根本没人接。这在 Meta 历史上从未发生过。

这就是我说的"AI 狂热症"——完全是自己造成的。这来自 Mark Zuckerberg，来自 Alexander Wang，来自顶层。他们在说："我们不在乎，构建这个模型对我们来说太重要了，我们愿意拿业务冒险，不在乎被黑什么的。"

士气跌到了 Meta 有史以来的最低点。这比 2022-2023 年的裁员还要糟糕得多。而且，在美国他们还在录制你的屏幕、记录你所有的键盘操作来训练 AI。

现在是从 Meta 招人最容易的时候。我交流过的工程师们感到被彻底辜负了——Meta 曾经把工程师当皇族对待，你能选择自己的团队，薪酬结构很好。而 CEO Mark Zuckerberg 本身就是软件工程师，他写了 Facebook 的大量代码。但现在工程师们感觉："我们不再重要了，我们是工具，被扔掉了。"

很多拿到高额留用奖金、没被裁的人也在面试——不是因为裁员本身，而是因为"我不知道下一个会不会轮到我去做数据标注"。作为专业人士，"我没有签约来做手动数据标注员"。

Meta 正在摧毁他们花 22 年建立起来的工程组织。我认为这可能是那个我所了解和热爱的、极其强大的 Facebook 工程文化的终结。

#### 过去六个月，一切都变了

不是所有公司都像 Meta 这么极端，但这些事情确实在发生。整个行业正处于一个非常有趣的时期。

##### DHH 的转变

DHH（David Heinemeier Hansson），Ruby on Rails 的创造者，今年二月上了我的播客。他去年夏天还在说 AI 没有直接写他的任何代码——部分原因是模型不够好。但现在翻转了：到二月份，他的大部分代码都是 AI 写的。这是一个极其注重软件匠艺的人，他不被任何实验室赞助，但他认定模型现在足够好了——"它们写的代码比我好"，他在播客上亲口告诉我的。

##### Simon Willison 的判断

Simon Willison——Hacker News 上被引用最多的人之一，独立软件工程师，Django 的创造者——他说 2025 年 11 月发布的模型，特别是 Opus 4.6 和 GPT 5.4，已经将 Agent 提升到了"真正有用"的水平。我们已经有六个月来适应这个想法了。

##### 数据佐证

来自 Linear 的数据（从未公开分享过）：使用 AI Agent 的团队比不使用的团队多产出 **5 倍**代码。这是不到两年内的巨大增长。

来自 Cursor 的数据：开发者年产出代码行数从 4000 行增长到超过 8000 行——将近 2.5 倍。PR 大小也增加了 3 倍。组合起来就是 6 倍的代码量。

同样来自 Cursor：不经任何人工审查就直接接受 AI 变更的开发者比例在一月份后大幅攀升——那时 Opus 4.7 和 GPT 5.5 发布了。

#### 科技公司巡览

##### Anthropic

Boris Cherny（Claude Code 的创造者）同时运行 5 个并行 Agent，每天提交 20-30 个 Pull Request——而且他还在领导整个 Claude Code 团队。他告诉我：PRD（产品需求文档）已死，Anthropic 全面使用原型来替代。Claude Code 100% 由 Claude Code 自己生成。Anthropic 内部 70-90% 的代码是 AI 生成的——没有指标要求，只是人们自然使用的结果。

公司用 10 天时间构建了 Claude Co-Work，这已经成为巨大的商业成功。我从 Microsoft 内部得知，Satya Nadella 给团队一个月期限来构建类似的东西——他们做不出来。

##### OpenAI

他们的内部版 ChatGPT 有一个"Fix It"按钮——你截个图，说"修这个 bug"，它就会发给 Codex，生成 PR，工程师（甚至非工程师）可以直接合并。他们有分层的审核：某些代码只需 AI 审核就能进生产，关键路径代码需要人类审核。

大多数开发者同时运行多个 Agent。有个笑话：工程师走路时笔记本半开着——这样本地 Agent 能继续跑。我采访一个 OpenAI 的人，问"面试期间你有 Agent 在跑吗？"他说："不是一个，是五个。"

OpenAI 内部大多数人已经不再手写代码了。Codex 团队还在用 Codex 改进自身——每天晚上它运行所有测试，寻找改进自己的方法，到早上给出改进建议供团队接受或拒绝。

##### Cursor

他们从一月起全力转向 Agent。他们构建了自己的编码模型——是 OpenAI 和 Anthropic 之外少数拥有优秀编码模型的公司之一。他们的 Composer 模型很便宜（这点后面会很重要）。他们运营着数万张 NVIDIA GPU，正在从纯推理转向同时训练模型——变成了一个迷你 AI 实验室。

Cursor 的每个人都很技术化。Lee Robinson（开发者关系负责人）用 Cursor 迁移了所有网站到新的 CMS——他不是职业软件工程师。

##### Google

Google 一切都是自定义的：IDE 叫 Cider（现在是 VS Code 分叉）、Jet Ski（内部版 Copilot）、Critique（代码审查工具）、Code Search（内部版 Sourcegraph）、Borg（内部版 Kubernetes）、Monarch（内部版 Datadog）、Piper（monorepo）。AI 集成在所有这些系统中，体验很好。

唯一的问题：Gemini 不如 Opus 或 GPT 5.5 好用。Google 内部工程师只要有机会就用 Claude Code，但他们被限制只能用 Gemini。Google 的 AI 采纳度因此不如其他公司。CEO 已经承认了这个问题。

##### Meta

他们要构建最先进的 AI 模型，一切都围绕这个。内部工具叫 Metamate。他们有一个叫"Trajectories（轨迹）"的功能——你在 Meta 内部的 GitHub 提交里能看到生成代码时的确切 prompt。去年十二月上线时没有告诉任何人，结果大家能看到 Staff Engineer 在问 AI"帮我写个 for 循环"。有人开始用波兰语写 prompt——因为懂的人少。

Mark Zuckerberg 想让 Meta 拥有比 Opus 4.8 更好的模型。要么未来几个月做到，要么大批人会极度士气低落。

##### Uber

我的老东家，约 3000 名工程师。他们的开发者体验团队（约 20 人）现在基本是"AI 体验团队"，构建了大量内部工具：

- **MCP Gateway**：内部 MCP 网关
- **Uber Agent Builder**：无代码 Agent 构建器
- **Uber Agent Studio**：拖拽组合 Agent
- **Agent Builder Registry**：给 20000 名非技术人员用
- **AI FX CLI**：基本是 Uber 版的 Claude Code
- **Uber Minion**：大规模后台 Agent 运行
- **Uber Code Inbox**：AI 代码审查优先级展示
- **Smart Assignments**：基于 SLA 的智能分配
- **Risk Profiles**：识别高风险代码变更
- **U Review**：内部版 CodeRabbit

其他大公司也在做类似的事：Stripe 有 Minions、Tool Shed、Blueprints；Shopify 有 Sidekick、LM Proxy、Dev MCP Server；Airbnb 有 One、Everything、Catalyst 等等。

##### 传统企业

也没有落后。Cisco 在一月份就向 18000 名工程师推出了 Codex。JP Morgan Chase 构建了一个多 Agent 框架来标注客户交互数据。

#### 跨行业趋势

##### 趋势一：从个体加速到系统级提效

Laura Tacho（前 DX CTO，现 AWS 开发者体验负责人）指出：很多组织只把 AI 当作个人生产力工具（邮件摘要、Slack 自动化、代码生成），但看到团队整体产出提升的公司，是那些从**业务目标**出发的——比如"我想更快部署到生产"或"在同等质量下推出更多功能"。

Spotify 是好例子：他们的 AI 使用标准是质量必须保持不变，所以产出增长不大，但他们构建了大量内部质量检查工具，刻意放慢 AI 推广节奏。

成熟度来自于**将 AI 应用到系统层面**，而非个体层面。

##### 趋势二：Token Maxing 与工具成瘾

在 Meta、Amazon、Microsoft 各处都有内部排行榜。人们被一种"看起来很高产"的压力驱动。AI 工具的定价模型也有成瘾性——你买了 $100 的计划，就觉得不用完很亏，于是越用越多。对某些人来说，每次 prompt 都像赌博——"再来一个 prompt"——人们睡眠质量下降，醒来就想着自己的 Agent。

##### 趋势三：中层管理被裁

管理者被裁员、被转为 IC（个人贡献者）、或被要求"更 hands-on"。组织在扁平化。

但好的中层管理——好的技术总监和高级工程经理——他们虽然可以 hands-on 但选择不这样做，因为他们在观察、倾听、做出小的调整来改善工程文化。当公司裁掉中层管理时，工程文化会下降，这是事实。

##### 趋势四：CEO/CTO 重新写代码

Vercel 创始人兼 CEO Guillermo Rauch 告诉我，他看到大量 CEO 和 CTO 带着狂热回归编码，上市公司 CEO 在私信他说"我们在用 Vercel 和 Claude Code，我好兴奋！"

现在想象一下：中层管理减少（不再保护工程师），而 CEO/CTO 在 Vibe Coding——他们觉得写完了，但其实没完。

##### 趋势五：AI 成本失控

Sam Altman 今天早上说他注意到 AI 预算正在成为很多公司的大问题——这是前所未有的。

Reddit 上有个段子："宝贝，我看到你共享账户里少了 $15,000……这是我想的那样吗？"

Anthropic 已经对企业客户开启按量计费。GitHub Copilot 两天前开始计费，人们在 3 天内就烧完了以前一个月的预算。Uber 的 CTO 在三月说他们烧完了全年的 AI 预算，现在设定每人每月 $1500 的上限，超出后只能用免费模型。

当 AI 成本跟一个工程师的工资一样高时，没有人愿意付这个钱。

##### 趋势六：质量断崖式下降

**Anthropic**：claude.ai 网站有一个月时间存在输入文字被页面刷新清除的 bug，影响数百万用户，没人修。直到我发推吐槽，产品经理才回复"好反馈，我来看看"——言下之意是"我们完全不知道这事"。

**OpenAI**：吹嘘用一个工程师六周构建了 Agent Builder，但质量很差，论坛里全是未解决的 bug 报告，三个月后有人说"它看起来就像弃坑了"。

**Amazon**：一个工程师让内部 AI 编码工具 Cairo 做变更，Agent 选择删除并重建一个环境，导致大规模故障。Amazon.com 的部分页面因 AI 生成的代码而宕机——这在以前从未发生过。Amazon 现在要求所有 AI 生成的变更必须有高级工程师审核。

**OpenCode**（Dax Raad 创立）：快接近百万日活用户了。Dax 非常坦诚地说："我们发布了太多 hack，本应该先从头重新设计系统。我认为我们的判断力偏了。"他还说："坦白讲，我不认为我们在很好地使用 AI。我们实际上在告诉自己少用点 AI。"——一个 AI 公司的 CEO 说需要少用 AI，这本身就是个矛盾。

**GitHub**：两周前所有 PR 消失了 8-12 小时。第三方追踪器估计 GitHub 连一个 9（90% 可用性）都没有——意味着某些部分 10% 的时间是宕机的。GitHub 团队告诉我是因为 2 年内负载增长了 3 倍——但真的吗？3 倍就能把 GitHub 打趴？

Mario Zechner（Pico 的创造者，OpenCode 的底层引擎）说得好："到处的软件都变成了脆弱的烂摊子。98% 的可用性感觉成了多数服务的常态。"

##### 趋势七："Slowburies"——还在坚守的工程师

PR 更多了，代码更多了，大部分是 AI 生成的。大多数开发者收到 review 请求后看到 AI 已经 review 过了就直接"LGTM"。但还有少数开发者仍在认真 review，仍在发现 bug，仍在推回去——他们正在被淹没、被烧完、感到不被奖励。绩效考核时他们不是那些"推出大量功能"的人。

他们有些人筋疲力尽后离职了。Dax 说 OpenCode 正在大量招聘这些人——因为他们受不了成为唯一一个还在维持质量的人，而工程管理层已经不存在了，没有人在乎了。

#### Kent Beck 的总结

Kent Beck 总结得很好："我们累积代码的速度快于我们累积信任的速度。"代码需要被信任、被理解，而我们现在没有时间做这些。

AI 放大了软件工程经验的价值——**资深者获益最多**，判断力被奖励。Hillel Wayne 说：能成功用 AI 生成 TLA+ 规范的人，无一例外都是 TLA+ 专家，他们在 prompt 里给出了精确的规范。初级工程师？祝你好运。

旧模式正在回归：Dax 告诉我他们在 OpenCode 里大量使用领域驱动设计（DDD）和详细的 guardrails——因为 **Agent 就是新的初级工程师**，你可以同时启动很多，但这些"初级工程师"需要大量约束。那些曾经因为冗长而不流行的企业级设计模式，现在恰好能约束 Agent。是时候掸去那些书上的灰尘了。

#### 给软件工程师的建议

##### 1. 放慢脚步才能加速

将每日 Agent 使用量限制在你能审查或验证的范围内。你不一定需要逐行读代码——Peter Shamberger（OpenClaw 创造者）说他发布自己不读的代码，但他构建了自己的验证系统，他用架构思维思考、让 AI 画架构图。

**不要交付超出你能验证范围的东西。**

##### 2. 技术债务现在很便宜

用 AI 来清除技术债务。成为你团队的"首席技术债务清除官"。别再觉得清除技术债务很难了——它不难了。如果你没在用 AI 清除技术债务，你就没有高效使用 AI。

##### 3. 多尝试不同的 AI 使用方式

没有放之四海而皆准的方法。跟朋友交流他们怎么用 AI，获取灵感。

**Mitchell Hashimoto**（HashiCorp 创始人）的规则："如果我在写代码，我让 Agent 在做规划；如果它们在写代码，我在做 review。"他只用一个 Agent——一个随时在身边的伙伴。

**Dax Raad**（OpenCode 创造者）：他以前 95% 时间思考、5% 时间写代码。现在有了 AI？"我能少花 25% 时间在编码上——所以现在是 96% 时间思考、4% 时间编码。"

##### 4. 不要将学习外包给 AI

Addy Osmani 说得好："让 AI 写代码太容易了，你跳过了所有学习。Bug 被修了，但你的心智模型没有更新。我们在用当下的速度交换未来的能力。"

每次使用 AI Agent 时，确保你从中学到了什么。

##### 5. 投资你的未来

- **构建基于 AI/LLM 的东西**：RAG、Evals、Agent 系统——AI Engineering 岗位正在爆发式增长，占所有软件工程岗位的 ~10%
- **理解产品和业务**：跟产品经理交流，理解商业运作
- **成为领域专家**：如果在农业公司就跟农民聊天，在汽车公司就跟机械工程师交流——当下次裁员来临，有领域专长的人最抢手

##### 6. 给工程管理者的建议

你需要保持 hands-on，否则这次你会被淘汰。用 AI 可以更容易做到这一点——让 AI 给你解释代码，开始贡献代码。你会做更少的人员管理，业务期望你这样做。

#### 最后的话

我跟 Martin Fowler、Grady Booch 等人都聊过，他们都说：**自 1960 年代以来，软件行业从未经历如此快速的变化。**12 个月内，AI 在编码工具领域全面普及。

如果你感到不堪重负——完全正常，很多人都是。我有时候也是。但偶尔拍拍自己的背：你跟上了，这很不容易。停下来看看四周，做出改变：我如何让这更可持续？我如何产出更高质量？我如何自动化一些东西？然后重复。

谢谢大家。
