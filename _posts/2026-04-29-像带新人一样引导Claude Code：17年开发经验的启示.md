Skyline 是一款由华盛顿大学 MacCoss 实验室首席开发者 Brendan MacLean 维护的开源蛋白质分析软件，自 2008 年起持续开发至今。Skyline 帮助研究人员检测和量化血浆、组织等样本中的蛋白质，这对生物标志物发现、疾病研究和药物开发至关重要。MacCoss 实验室的代码库包含超过 70 万行 C# 代码，由一个小团队维护了 17 年，每晚运行超过 20 万个自动化测试。

近三十年来，Brendan 一直是 Skyline 的核心纽带，他为实验室引导了数十名本科生、研究生和博士后。

随着开发者的加入和离开，代码库不断吸收他们的贡献。到 2024 年，它已经承受了长期项目的惯有负担——某些区域随着开发者的更替变得无人敢碰。

在数十年培训实验室成员的过程中，Brendan 深知如何让研究人员快速上手实验室庞大的代码库。他没有想到的是，将同样的方法论应用于 AI 工具，竟然能让 Skyline 的代码库重新变得可管理。

#### 同样的引导问题，不同类型的开发者

Brendan 最初对现代 AI 编码工具持怀疑态度——他不相信它们能像专门为该语言和环境构建的工具那样理解 C# 代码。

在浏览器中使用 Claude.ai 的早期实验证实了这种模式。他描述一个问题，得到一个回答，然后将整个 C# 文件复制回项目中，将范围限制在无需引用项目代码就能描述的独立问题上。

"一旦修改变得更加增量化，这就变得非常费力了，"Brendan 说。

每次与 Claude.ai 的会话都像从零开始——它不了解 Skyline 是什么，组件之间如何关联，也不知道 17 年的开发积累了什么。

这与 Brendan 引导新开发者时面临的体验完全相同，这给了他一个灵感。

> "我可以像引导一名受训开发者一样，通过 Claude Code 将 Claude 引入我的大型项目：解释足够多的信息以成功完成一个有限的项目，并为下一次迭代生成改进后的上下文。"

他将所有 AI 上下文移入一个独立的仓库 `pwiz-ai`，与代码库分离存放，这样它就能跨所有分支和时间点通用。根目录下的 `CLAUDE.md` 文件负责环境设置，并将 Claude 指向相关文档——可以把它看作"全局概览"，而非专业知识本身。

专业知识存在于**技能（Skills）** 中。技能是一种开放格式，用于赋予智能体能力和专业知识。例如，他的调试技能旨在将 Claude 从"猜测与测试"模式中拉出来，推动它在尝试任何修复之前先进行根因分析。技能可以手动或自动触发；Brendan 用明确的条件来调优最关键的技能——调试技能的描述写着："在调查 bug、故障或意外行为时**始终**加载。"

有了上下文的基础，教 Claude 代码库调试的开销就大大降低了。Claude 已经知道代码是做什么的。交互从理解开始，而不是从零开始。

> "一个看似重大的担忧——'Claude 无法真正了解我的大型项目'——变得越来越清晰：**上下文只是另一个需要维护和发展的工件**。"

#### 减少技术债务，加速开发

在 Skyline 中构建文件视图面板（Files View panel）的项目——一个新界面，展示所有文档相关文件，具备文件系统监控和拖放组织功能——在负责该项目的开发者离开后搁置了一年。Brendan 用 Claude Code 接手了这个项目。

两周后项目完成了，所有最终提交都由 Claude 联合署名。

> "之前留在这种状态的工作通常最终会被丢弃，"Brendan 说。

在学术实验室中，开发者经常轮换——研究生毕业、博士后转岗、实习生夏末离开。过去，任何半成品的工作都会永远被搁置。

三年前，Brendan 在失去维护开发者后停止了为 Skyline 的夜间测试管理模块添加功能。该模块使用 Java 编写，是 LabKey Server 科学数据 Web 门户的一部分。最近，在一位技术熟练的 LabKey 开发者使用 Claude Code 创建了设置文档之后，Brendan 花了不到一天的时间就添加了他多年来一直想要的功能，并用 CSS 更新了页面布局——而过去他只雇设计师来完成这类工作。

新的基础设施也随之而来。

Skyline 2000 多张教程图片的截图复现现已完全自动化且几乎 100% 可复现，通过 Claude Code 扩展了差异视图和像素变化放大功能，以及一个由 Claude 用 C# 编写的 MCP 服务器，使其能够"看到"这些差异。Claude Code 每天早上生成一份摘要，展示测试失败、异常和开放的支持工单，这些数据从 Skyline 的夜间测试基础设施中提取，在 Brendan 坐下工作之前就送到他的收件箱。

Claude 还用 Python 编写了 MCP 服务器来实现这一能力，从 LabKey Server 上的三个独立关系数据流、团队邮件以及 GitHub 上带有发布标签的代码中获取数据。

Brendan 的开发者们现在几乎不再自己写代码，主要是指导 Claude Code，并使用该工具自主生成自动化脚本和 MCP 实现。例如，实验室中一位曾对智能体编码工具持怀疑态度的开发者构建并发布了一个新的绘图扩展——用于可视化离子迁移率数据的 mobilogram 面板——并归功于 Claude Code。

> "我看到几乎每个人都在接手有趣的新功能，这些功能他们之前可能因为深陷其他工作而无暇尝试。"

#### 给处理遗留代码库的开发者的建议

基于 17 年引导开发者的经验以及超过一年将同一方法论应用于 Claude Code 的实践，以下是 Brendan 给处理遗留代码库的开发者的建议。

##### 上下文是你最好的朋友

Claude 生成的待办事项列表和计划不会跨会话持久化。**上下文**才是持久化的东西，而且必须刻意维护。这是大多数开发者跳过的部分，也是大多数开发者的成功为何会见顶的原因。

> "要明白，如果你不记录'上下文'，Claude 就无法学习。不要期待魔法。投入精力构建和维护你的上下文层。并像对待其他项目工件一样对待它：进行版本控制、发展它、维护它。"

Brendan 将 AI 上下文保存在一个独立的仓库中，因为它的增长速度与代码不同，且适用于所有分支和时间点——将其放在代码仓库内部已经变得越来越受限。将上下文保存在同一个仓库中也是一种有效的替代方案；重要的是它要被版本控制、维护，并在需要时可用。

##### 投入构建你的技能库

使用技能来编码领域知识，任何 Claude 实例都可以加载。Brendan 的技能遵循"引用而非嵌入"原则：每个技能指向一个中央文档知识库，而不是复制内容，这样就能保持轻量且易于维护。

他最常用的技能包括：
- **skyline-development 技能**：为 Claude 介绍项目及其文档
- **version-control 技能**：编码项目特定的提交和 PR 约定
- **debugging 技能**：旨在将 Claude 从"猜测与测试"模式中拉出来，推动它在尝试任何修复之前先进行根因分析

##### 在数据访问是关键时使用 MCP 集成

在 Claude 需要访问真实数据的地方构建 MCP 集成：测试结果、异常报告、支持工单。

对于开源项目，构建和维护上下文层具有特殊的分量。没有引导预算，没有超出书面记录的组织记忆，也无法保证任何贡献者明年还在。上下文一旦构建完成，就可以供每位贡献者使用，并以人类组织知识永远无法做到的方式在项目的整个生命周期中持续存在。`pwiz-ai` 仓库本身就是一个开源工件——属于项目而非任何单个贡献者的上下文，它比构建它的每个人都更长久。

#### 十七年引导经验，一个结论

你不会把一个 70 万行的代码库交给新入职的员工，然后期望他们第一天就出成果。你会为他们找一个可控范围的项目，陪他们走通，然后随着他们理解的加深逐步扩大范围。

正如 Brendan 所发现的，你为 Claude 构建的上下文也是同样的道理。

一旦对代码库足够了解，工程师就能跨分支、跨时间点工作。Claude 在获得足够的上下文和指导后，同样可以做到。
